            MCP Endpoint Authentication
            
        
            
        
            
          
          
            
            
            
            
          
            
          
          
        
            
        
            
          MCP token editing is disabled on this server (--no-token-edit).
        
            
      
            
      
            
        
            API Read Token
            
        
            
        
            A second credential for tools that only read from this API — the tool router, the control tool in read-only setups. Valid on GET requests only, and never for the MCP token or an instance export. Without it such tools have to carry the admin password, which grants everything.
            
        
            
          
          
            
            
            
            
          
            
          
          
        
            
        
            
          Token editing is disabled on this server (--no-token-edit).
        
            
      
            
      
            
        
            Agent Token
            
        
            
        
            For agents that also write — the control tool with its write actions enabled. Valid on every method, but never for the password or the token fields on this page: an agent that could set a new password would be an admin. Its reach is otherwise the admin's, including uploading and running code, so treat it as a rotatable stand-in for the password, not as a sandbox.
            
        
            
          
          
            
            
            
            
          
            
          
          
        
            
        
            
          Token editing is disabled on this server (--no-token-edit).
        
            
      
            
      
            

      
            
      
            
        
            User Identity (OpenWebUI)
            
        
            
        
            Lets an instance know which person is calling, not just that the client is allowed to. Set the same secret OpenWebUI signs with (FORWARD_USER_INFO_HEADER_JWT_SECRET, together with ENABLE_FORWARD_USER_INFO_HEADERS=true). Per instance, switch User identity in its config; access rules live in runtime/identity_policy.json. Write-only: it is never shown again, because it is a copy of what OpenWebUI already has.
            
        
            
          
          
          
          
          
          
        
            
        
            Only needs ENABLE_FORWARD_USER_INFO_HEADERS=true in OpenWebUI, no shared secret. It separates the users of your OpenWebUI installation from each other — but the headers are a claim, not a proof: anyone who can reach an instance's port with the MCP Bearer token can write them by hand. Choose it when that port is not reachable by anyone you are guarding against; otherwise use the secret.
            
        
            
          Token editing is disabled on this server (--no-token-edit).
        
            
      
            
      
            
        
            Agent Identities
            
        
            
        
            A token per calling agent — Claude Code, Codex, a cron job. Behind the shared MCP Bearer token they are all the same caller; with one of these each has a name, so the access rules, the usage figures and the log can tell them apart. Assigned, not proven: whoever holds the token is that agent. Give rights to it in Users & permissions, where it appears under its id.
            
        
            
        
            
          
          
          
          
        
            
        
            
          
            Copy this token now — only its hash is stored, so it cannot be shown again.
            
          
            
            
            
          
            
        
            
        
            
      
            
      
            

      
            
      
            
        
            Shared MCP Port
            
        
            
        
            Expose all MCPs through one port as /mcp/<id> instead of one port per instance. Instances then bind to localhost only; already running instances pick this up on their next restart.
            
        
            
          
          
          
          
        
            
      
            
      
            
        
            Instance Endpoints
            
        
            Serve every running instance as /mcp/<id> on this manager's port too — the same forwarding the shared port does, without a second port. Off by default: an instance that binds to localhost becomes reachable from outside the moment this is on. Rights are decided by the instance, as on a direct connection. Existing URLs keep working; the shared port above is unaffected either way.
            
        
            
          
          
        
            
      
            
      
            
        
            Category Endpoints
            
        
            Serve every running instance of one category as a single MCP server on this manager's port, under /mcp/category/<name>, with tools named <instance>.<tool>. Off by default — one endpoint reaches a whole category at once, so it is switched on by a person rather than by an upgrade. The MCP Bearer token applies; rights are decided by the instance, as on a direct connection. While they are on, every category is listed below with its URL and an OpenWebUI export; the dashboard shows the same for whichever category its filter is set to.
            
        
            
          
          
          
          
        
            
        
            
      
            
      
            
        
            Virtual Environments
            
        
            Each instance runs in its own venv so dependencies stay isolated. The default venv is always available.
            
        
            
        
            
          
          
        
            
      
            
      
            
        
            Health Check
            
        
            Every minute the manager asks each running instance for its tool list — the same request OpenWebUI makes. A wedged runner keeps its process and its open port, so only an answer proves it is alive. Auto-restart is off by default; when it is on it gives up after three restarts and leaves the instance alone.

            File Storage
            
        
            
        
            Instances with File storage switched on write into content/<id>/. A link the tool returns is rewritten to a download URL of this server carrying a token for that one file — that link and the control tool are the only two ways in. There is no directory listing and no guest view.

            Usage Tracking
            
        
            Every tool call is recorded with time, instance and function in runtime/usage.db — never arguments or results. Individual calls are deleted after the retention window; the totals per function are kept, so ever used stays answerable.
            
        
            
          
          
        
            
      
            
      
            
        
            Update Check
            
        
            
        
            Off by default. When enabled, the server asks the GitHub releases API once a day whether a newer version exists — an outgoing request that tells GitHub this installation exists. Nothing is downloaded or installed; you only get a link in the header.
            
        
            
          
          
        
            
        
            
      
            
      
            
        
            Backup & Restore
            
        
            Everything worth restoring in one file: the instance configurations, their tool code, the server settings, the access rules and the agent roster. Not included — the venvs (rebuilt through the normal install path), the stored files under content/, the identity roster and the usage numbers.
            
        
            
          
          
        
            
        
            
        
            Restoring never overwrites: an instance whose id already exists is skipped and named, a setting already set stays, and the file key is only written where there is none. Check first shows what would happen without changing anything.
